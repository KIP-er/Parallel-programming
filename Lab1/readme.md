# Lab1 — Умножение матриц

Лабораторная работа №1: умножение квадратных матриц на C++.
Цель — реализовать алгоритм умножения, провести эксперименты для разных
размеров матриц и проверить корректность результата независимой реализацией
(NumPy).

## Структура

| Файл | Назначение |
|---|---|
| `CMakeLists.txt` | Сборка C++ проекта |
| `matrix.cpp` | Точка входа: меню, чтение, умножение, замеры, запись |
| `Matrix.cppm` | Модуль класса `Matrix` (квадратная, row-major) |
| `gen.py` | Генератор случайных матриц заданного размера |
| `bench.py` | Прогон по размерам, сбор `benchmark.csv` |
| `verify.py` | Независимая проверка через NumPy |
| `plot_perf.py` | Построение графиков времени |
| `requirements.txt` | Python-зависимости |
| `matrix_a.txt`, `matrix_b.txt` | Примеры входных матриц |
| `result.txt` | Результат умножения (создаётся при запуске) |
| `benchmark.csv` | Таблица замеров (создаётся `bench.py`) |
| `performance.png` | График (создаётся `plot_perf.py`) |

## Алгоритм

**Последовательное умножение (`Matrix::multiply`):**

- порядок циклов `i, k, j` — cache-friendly для строчного хранения;
- внутренний цикл идёт по непрерывной памяти `b(k, j)` и `result(i, j)`;
- сложность O(N³), число арифметических операций 2·N³.

Матрицы читаются из `matrix_a.txt` и `matrix_b.txt` и записываются в
`result.txt` в формате: первая строка — N, далее N строк по N чисел.

## Сборка

```
cmake -S . -B build
cmake --build build --config Debug
```

Или через Visual Studio: открыть папку `Lab1` как CMake-проект → Build All.

## Запуск

**1. Установить Python-зависимости (один раз):**

```
py -m pip install -r requirements.txt
```

**2. Сгенерировать матрицы:**

```
py gen.py 500
```

Аргумент — размер N; если не указан, используется 200.

**3. Запустить C++ программу:**

```
.\build\Debug\matrix.exe
```

В меню выбрать `2` (умножить) — программа сама вызовет `verify.py` и
напечатает `RESULT: OK`. Затем `5` для выхода.

**4. Полный эксперимент по размерам и графики:**

```
py bench.py
py plot_perf.py
```

`bench.py` прогоняет размеры 200, 400, 800, 1200, 1600, 2000, сохраняет
замеры в `benchmark.csv` и печатает готовую Markdown-таблицу.
`plot_perf.py` строит `performance.png`.

## Проверка корректности

`verify.py` выполняет независимую проверку:

1. Читает `matrix_a.txt`, `matrix_b.txt`, `result.txt`.
2. Считает эталон через NumPy: `a @ b`.
3. Сравнивает с результатом C++ через `np.allclose` (rtol = atol = 1e-9).
4. Печатает максимальное абсолютное расхождение и `RESULT: OK / FAILED`.

Все результаты совпадают с эталоном: `max |C_cpp − C_numpy| = 0.000e+00`.

**Левый график** — время vs N. Пунктиром нанесена теоретическая кривая O(N³),
масштабированная по первой точке. Измерения практически совпадают с ней.

**Правый график** — нормированное время `time / N³`. Для строго кубического
алгоритма точки лежат на горизонтальной прямой; здесь значения в диапазоне
≈ 8800–9230 нс/операцию, то есть практически постоянны (разброс ≈ 5 % —
шум замеров и эффекты кэша).

## Выводы

1. Результаты умножения полностью совпадают с эталоном NumPy для всех
   размеров (`max diff = 0`, `RESULT: OK`).
2. Время растёт примерно как N³: при увеличении N в 10 раз (200 → 2000)
   время растёт примерно в 1000 раз, что соответствует теоретической оценке.
3. Нормированное время `time / N³` почти не зависит от N — дополнительное
   подтверждение кубической сложности.
4. Умножение реализовано вручную циклами, без сторонних матричных
   библиотек — это позволит в следующих работах добавить распараллеливание.
5. Верификация автоматизирована: C++ программа сама запускает `verify.py`
   после умножения, результат проверяется сразу.
